# debuff friction log

Things that got in the way while building Overbuffed. Each one should become a fix in debuff.

- [x] `create-debuff --help` prints the banner and "Pass a directory" instead of usage/options. Fixed in debuff 9a3a441.
- [x] CLI output (`debuff test`, `debuff build`) keeps ANSI colours when stdout isn't a TTY (agents/CI logs fill with escapes). Respect `isTTY` / `NO_COLOR`. Fixed in debuff 9a3a441.
- [x] **keiko hangs forever when the game loads assets** (debuff 0.5.0, Windows). `npx debuff test` prints the banner and never finishes, even with `-t` on a trivial test, no error and no boot timeout. Bisected: stubbing out `assets.load()` makes tests pass in ~1.5s. Scenarios in a real browser load the same assets fine. Logic tests are blocked until this is fixed. Fixed in debuff a586450: Vite's dependency optimizer ran on keiko's virtual timers and deadlocked.
- [ ] Default `draw.text` font is smooth, not pixel; a pixel-art game wants a pixel font out of the box (or a one-line way to get one). Overbuffed now draws its own (buffont); candidate to ship with debuff.
- [ ] Scenario `contrast` downsamples regions wider or taller than 256 px (`luminance(min(256, w), …)`), which averages 1-px pixel-font strokes into the background and understates contrast: a 288-px row of level-up cards read 4.36:1 while each card alone passes. Sample at native resolution (or tile), and say in the failure which colours it compared.
- [ ] `debuff scenario <name>` treats the argument as a file path (`ENOENT: …\late-game`); accepting a scenario name (or `-t`) like `debuff test` would be friendlier.
- [ ] `debuff fuzz` flags any numeric state that oscillates as a "loop": `state.shots` going 0→1→0 as bullets fire and expire was reported 3 times in 3 minutes. Loop detection should look at position/scene/progress, or let `inspect()` mark fields as noisy (e.g. a `fuzz: { ignore: ["shots"] }` option).
- [ ] `debuff fuzz` "stuck" fired on the level-up screen: the cursor moved but wasn't in `inspect()`, and the fuzzer rarely presses confirm keys with fresh edges. Fixed in the game (cursor in state, Z confirms); the report could say which keys it never pressed fresh.
- [ ] Follow-cam jitter: `Camera` defaults to `lerp = 8` and snaps its view to whole pixels, while the followed sprite is drawn at its own fractional interpolated position, so the player shimmies 1px against the world when moving. Fixed in the game by locking the camera (`lerp = 0`) and drawing buff at the same rounded point. debuff could snap the follow target the same way the view snaps, or document the pattern.
